## Details

- US1 sc1 (PASS): Navigated to /emails with a fresh DB, before sync. The "Emails" nav link had aria-current="page" (verified via DOM getAttribute). The page showed a Naive UI n-empty component with text "No conversations yet" and data-testid="emails-empty", not a list. Screenshot: 01-emails-empty-state.png.

- US1 sc2 (PASS): After creating Sam Rivera (with a second address sam.personal@example.com) and Ana Alvarez (no email) via the People page form, and running a sync (2026-07-01 to 2026-08-08, reported "30 new, 0 updated", status "success", screenshot 02-sync-success.png), the /emails list showed "Quote attached" (Aug 6, 2026, 5:00 AM local) as the first row and "Pricing question" (Aug 5, 2026, 11:00 AM local) as the second row, newest-first confirmed. Each row showed subject, participant names, a message count badge, and a latest-message date. DOM check confirmed: "Quote attached" row has both [data-testid="unread-indicator"] and [data-testid="attachment-indicator"] (paperclip emoji); "Pricing question" row has neither. "Meeting notes" (the inline-attachment-only conversation) row also has no attachment-indicator, confirming FR-004 edge case: an inline-only attachment does not trigger the paperclip icon. Screenshot: 03-emails-list-25-before-loadmore.png.

- US1 sc3 (PASS, re-verified after a seed fix): Initial page load showed exactly 25 rows with data-testid="email-conversation-row" and a "Load more" button (confirmed via querySelectorAll count = 25). On the first run, clicking "Load more" revealed only 29 total conversation rows, not 30 — root cause was an off-by-one in `src/server/services/email/dev-seed.ts`: `FIXED_CONVERSATION_COUNT` was set to 6 (counting seed messages) instead of 5 (distinct conversations), since `pricingQuestion`/`pricingReply` share one conversation. Fixed to `FIXED_CONVERSATION_COUNT = 5` (`FILLER_COUNT` becomes 25), full gate re-run green (69 files / 733 tests), dev server restarted against a fresh DB, sync re-run, and the scenario re-verified live in the browser: initial load showed exactly 25 rows (rowCount=25) with "Load more" present, and after clicking it showed all 30 rows (rowCount=30) with the "Load more" button gone (buttons=[]). Screenshots: 19a-us1-sc3-25rows-before.png (25 rows), 19-us1-sc3-fixed.png (30 rows, no Load more button). Superseded prior screenshots 03/04 for this scenario, which showed the pre-fix 25/29 state (03 is still cited for US1 sc2's list-ordering evidence, which was unaffected by the count bug).

## Post-evidence fixes (verifier findings, applied before merge)

- Fixed duplicate address rendering on the conversation detail page: unmatched participants with a display name showed `Name <addr><addr>` (`EmailConversationPage.vue`) — the address was emitted twice, once inside the display-name label and once in the separate address span. Now shown once.
- Fixed the unread indicator dot (`EmailsPage.vue`) having no CSS rule and painting nothing; it now renders as a visible small blue dot. The bold-row styling was already correct and remains the primary unread cue.
- Fixed `PersonEmailSection.vue` flashing its "No synced email" empty state before the fetch resolved, even for people who do have synced mail — now gated on a `loaded` flag, matching `EmailsPage.vue`'s pattern.
