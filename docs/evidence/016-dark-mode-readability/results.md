# 016-dark-mode-readability — browser evidence

Feature: app-wide dark-mode readability overhaul (chat-directed by Tyler, 2026-08-11; no docs/product feature spec — design decisions recorded in the PR description). Dev server: `MAIL_PROVIDER=fake npm run dev` on branch ports (API 3016 / UI 5116), seeded with 3 people, the fake-provider mailbox (sync window 2026-08-01 → 2026-08-11, 6 messages), and one board task. All criteria executed by the `browser-tester` agent against http://localhost:5116; measured values below are computed styles read from the live DOM. Screenshots live alongside this file (gitignored by the evidence-dir convention; only results.md is tracked).

Automated acceptance gate: `tests/unit/palette.test.ts` computes WCAG contrast ratios over `src/client/palette.ts` (AA ≥ 4.5:1 for every text tier, link, and error color on every surface it sits on; ≥ 7:1 for primary text and the email light card) and pins the Naive UI theme overrides plus the `--wh-*` CSS-var map to the palette. Component tests cover the email light card markup (`tests/component/email-body.test.ts`), the CSS-var binding on the app shell (`tests/component/app-shell.test.ts`), and the Tags-cell layout fix (`tests/component/people-page.test.ts`). Full gate at completion: 72 files / 806 tests passed, lint clean, typecheck clean, build clean.
