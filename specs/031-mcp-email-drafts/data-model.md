# Data Model: MCP Email Drafts

**Feature**: `031-mcp-email-drafts` | **Date**: 2026-08-27

This feature adds one column and one key-value entry; everything else reuses the existing email schema (`src/server/db/schema.ts`). Decisions behind each shape are in [research.md](research.md).

## Schema changes

### `email_messages` — new column `is_draft`

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `is_draft` | integer (boolean mode) | NOT NULL, DEFAULT false | True while the message is a draft in the mailbox's Drafts folder. Mirrors Graph's `isDraft`. |

Migration: `drizzle/0008_*.sql`, generated by `npx drizzle-kit generate` after editing `schema.ts`. Purely additive — every existing row gets `false`, which is correct (drafts were excluded from sync until now), so no hand-adjustment and no data loss. Landed migrations `0000`–`0007` are untouched.

No index: draft rollups ride the existing per-conversation queries and the table is personal-mailbox scale.

### `app_state` — new key `email.signature`

| Key | Value |
|---|---|
| `email.signature` | The signature as one HTML string, exactly as saved in the panel. Absent (or cleared via whitespace-only save) means "no signature saved" — creation proceeds signature-less. |

No schema change; `app_state` is the existing key-value table with `getAppState`/`setAppState` accessors.

## Entities and their lifecycles

### Draft (a row in `email_messages` with `is_draft = true`)

Same row shape as any synced message — `graphMessageId` (immutable Graph id, unique), `conversationId` → `email_conversations`, `sourceFolder` (display name "Drafts"), `subject`, `bodyOriginal`/`bodyContentType`/`bodyText`, `sentAt`/`receivedAt`, read/importance/flag/categories metadata, participants via `email_participants` (roles `from`/`to`/`cc`/`bcc` — bcc already exists in the enum).

**What makes drafts different is the update rule.** Non-draft messages keep the snapshot rule: content fields (`subject`, `bodyOriginal`, `bodyContentType`, `bodyText`, participants) are written once at first ingest and never refreshed. Draft rows are the specced exception (FR-016): the mirror path rewrites all content fields on every encounter — sync's Drafts pull, `update-draft`'s response ingest — with participants replaced wholesale (delete + reinsert, the way attachments already refresh). The ranged sync's metadata refresh list additionally gains `is_draft`, so a sent draft's row flips to non-draft (and from then on snapshots) when its id reappears in a normal folder.

**State transitions**:

| Transition | Trigger | Store effect |
|---|---|---|
| (none) → draft | `create-draft` / `create-reply-draft` tool, or sync's Drafts pull finding a hand-started draft | Insert row with `is_draft = true`; upsert conversation by `graphConversationId` (fresh draft: new conversation; reply: existing conversation) |
| draft → draft (content changed) | `update-draft` tool, or sync's Drafts pull seeing an Outlook edit | Mirror-update all content fields + participants |
| draft → gone | `delete-draft` tool, or sync reconciliation (discarded in Outlook) | Delete row + participants; delete conversation if empty |
| draft → sent message | Tyler sends from Outlook; next sync | Row flips `is_draft = false` when the sent copy is ingested from a ranged folder; if the sent copy isn't in this run's range, reconciliation removes the draft row and a later covering run re-ingests the message normally |

**Validation rules** (enforced in service/tool layer, per FRs):

- Create: at least one `to` recipient; `subject` is a required parameter (any string — the mailbox permits empty subjects, and the tool passes it verbatim); `bodyHtml` must be non-empty after trim (FR-022).
- Reply create: target `messageId` must exist in the store (any synced message, draft or not).
- Update/delete: target `messageId` must exist **and** have `is_draft = true` (FR-011) — the guard is a store check made before any mailbox call.
- All writes: mailbox write succeeds before the store is touched; a Graph 404 on update/delete leaves the store unchanged (next sync reconciles).

### Signature

Work-helper's own single HTML block (`app_state['email.signature']`). Read at draft-creation time and appended below the supplied body (before the quote, for replies); never consulted by `update-draft`; never synced from or written to Outlook.

### Conversation (existing `email_conversations`)

Unchanged shape. New behaviors: a conversation can now be created by a draft (fresh `create-draft`), can contain a mix of drafts and real messages, and is deleted when its last message (e.g. its only draft) is removed. Conversation summaries gain a computed `hasDraft` rollup (`MAX(is_draft)` over messages), not a stored column.

### Sync run (existing `sync_runs`)

Unchanged shape. Semantics per research R6: the Drafts phase's inserts/updates fold into `newCount`/`updatedCount`; reconciliation removals are uncounted; draft tool writes never create rows here.

### Mailbox connection

Unchanged (MSAL file token cache). No stored scope tracking — write permission is probed live via `getWriteAccessToken()`. The `MailWritePermissionError` message is generalized (research R3).
